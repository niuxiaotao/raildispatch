# 航空学：轨道调度 · Rail Dispatch

给 **Create: Aeronautics（航空学）/ Simurail** 的物理车辆，补上 Create 蒸汽火车那一套自动化：
**读时刻表 → 看信号机 → 申请进路 → 停车/运行 → 按标签找车与找股道。**

> 详细设计与取舍见 [`docs/DESIGN.md`](docs/DESIGN.md)。

---

## 环境

| 项 | 要求 |
|---|---|
| Minecraft | 1.21.1 |
| 加载器 | NeoForge 21.1.233（`[21.1.233,)`） |

| 可选 | **Create: Railways**（道岔方块在这里，装了才能被调度中心/自动驾驶台驱动道岔） |

## 构建（离线）

本机没有外网，**Gradle 不可用**（`moddevgradle` / `foojay` 插件与 neoform 管线都需要联网下载，已实测失败）。
所以工程里**刻意没有 `build.gradle` / `settings.gradle`**——写了也跑不起来，只会误导；`gradle.properties` 保留，
因为它是版本元数据的唯一来源，也是离线脚本做 `${占位符}` 替换的数据源。
构建改为直接对着启动器已有的 jar 用 `javac` + `jar` 编译打包：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
cd D:\DS_WORKSPACE\raildispatch
& .\tools\build-offline.ps1
```

产物：`build\libs\raildispatch-0.1.0.jar` → 丢进实例的 `mods\` 即可。

脚本会自动找出"装了物理转向架的那个实例"（按有无 `simurail*.jar` 打分），并自动推导 MC / NeoForge 版本。想指定别的实例：

```powershell
& .\tools\build-offline.ps1 -Instance '1.21.1-NeoForge_21.1.228航空学超级整合包'
```

> ⚠️ 脚本刻意保持**纯 ASCII**：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 脚本按 ANSI 读，
> 脚本里写中文实例名会直接崩。中文字符串只出现在 `src/` 下的资源与 Java 源码里（javac 指定了 `-encoding UTF-8`）。

顺带生成的贴图同样可复现：

```powershell
& .\tools\make-textures.ps1        # 重画 8 张 16x16 贴图
& .\tools\validate-resources.ps1   # 校验资源（构建流程已自动调用）
```

`validate-resources.ps1` 专门查 javac 看不见的那类错误：**方块状态变体漏了**（无属性方块的状态键是空字符串，
PowerShell 5.1 自带 JSON 解析器处理不了）、模型或贴图路径解析不到、注册了方块/物品却没有模型或没有翻译。
构建时它会先跑，不通过就直接失败——否则这些错误要等进游戏才发现是"方块隐形"。

## 上手

### 1. 物理驾驶台 `physics_cab`

**这是唯一会操纵整辆车的方块。**

1. 放在物理车体上（放在车上、随结构一起组装）。
2. 装入时刻表：**潜行 + 右键**驾驶台。⚠️ 不能直接手持时刻表右键 —— Create 的 `ScheduleItem` 会把普通右键
   抢去打开**它自己的**时刻表编辑界面并吞掉这次交互（`use()` 返回 `success`），潜行时它才返回 `pass` 让交互落到方块上。
   - 也可以：**空手右键**打开驾驶台界面，再把时刻表从背包拖进槽位。
   - 取出时刻表：**潜行 + 空手右键**（原时刻表会还给你，不会被删除）。
3. 驾驶台会自己认车并开始按状态机跑。

界面显示：条目进度、当前状态、**前方信号灯色**、速度、进路是否锁闭、驱动了几个转向架。

| 状态 | 含义 | 比较器输出 |
|---|---|---|
| 空闲 | 没车 / 没时刻表 | 1 |
| 申请进路中 | 等地面层给进路 | 4 |
| 运行中 | 绿灯正常运行 | 8 |
| 接近 | 减速接近（黄灯 / 目的地 / 红灯前） | 11 |
| 信号机前停车 | 红灯停稳 | 15 |
| 等待中 | 到站停车等点 | 6 |
| 已到达 | 条目完成 | 2 |
| 连挂中 | 接近目标车辆 | 10 |

**信号行为**：`lookahead`（默认 64 格）内找到信号机就按它的灯色走；红灯按匀减速曲线在信号机前 `brakeMargin` 格处停稳；黄灯限速爬行（可关）。

### 2. 换向器 `reverser`

贴在**物理转向架**旁边（默认 8 格内同属一辆车的转向架都会被它驱动），把转向值灌进转向架。

红石约定（模拟信号强度）：

| 信号 | 转向 |
|---|---|
| 0 | 放开（把控制权还给转向架自身） |
| 1 | 左满舵 |
| 8 | 直行 |
| 15 | 右满舵 |

- 右键查看当前转向值与驱动到的转向架数量；比较器输出把 `-1..1` 映射到 `0..15`，可以直接读表。
- 放成倒向时把方块的 `inverted` 属性翻过来即可反向，不用改红石接线。
- **驾驶台一旦接管同一辆车，换向器自动转为被动**，不会和驾驶台抢转向架。

### 3. 车辆标签 `vehicle_tag`

**给车取名，让时刻表能指名道姓地找它。**

1. 铁砧上把标签改名（比如 `煤车3号`）。
2. 右键**那辆车**（或车上的物理驾驶台）完成绑定。

之后时刻表里就能用这个名字寻址：`连挂车辆 → 煤车3号`、或者直接把目的地写成这个名字让车开过去。

### 4. 地址标签 `address_tag` + 地址牌 `address_plate`

**驼峰调车场的去向识别。**

- 拿改好名的地址标签：
  - 右键**车辆** → "这车的去向是 X"
  - 右键**地址牌** → "这条股道承接去向 X"
- 地址牌放在股道上，右键可查看它登记的去向。

调度读取每辆车的去向编码，和股道的去向匹配，就知道该把它送进哪条道。

### 5. 调度中心 `dispatch_center`

**可选**。放了它，就由它统一仲裁进路；不放，驾驶台自己规划并锁闭。

**放置方式与列车信号机完全相同（两步）：**

1. 手持调度中心 **右键铁轨** → 选中那条轨道（会有 Create 自己的提示音与反馈）。
2. 再 **右键一个可放置的位置**（铁轨旁的地面/方块）→ 方块落下，并自动绑定到刚才那条轨道。
3. 潜行 + 右键可**清除已选轨道**。

> 没选轨道就直接放会被拒绝并提示（`track_target.missing`）—— 这是 Create 的行为，不是 bug。
> 正因为绑定了轨道，调度中心**知道自己管辖哪条铁路**，而不是靠半径猜；右键时会显示"已锁定轨道 X"。

其余行为：

- 默认作用范围 256 格。
- 右键查看持有多少条进路、每条给谁、多长、锁定的是哪条轨道。
- 比较器输出随持有进路数上升。
- 两条进路的岔路口重合、或路径点距离小于 4 格 → 判为冲突，后来者被拒绝并给出可读原因。
- 车辆超过 `routeTimeoutTicks` 没动过 → 自动释放进路（防幽灵锁闭）。
- 拆掉方块会同时从轨道图上摘掉它的点位；没装管线时**不会**留下幽灵点位。

### 6. 自动驾驶台 `autopilot_console`

**输入目的地，按「启程」，车自己开过去。** 不需要 Create 时刻表。

1. 装在物理车上，随结构一起组装；**站在车尾、让屏幕朝向你**放置——车会朝你放置时看的方向
   （屏幕的反方向）开。它只朝这个方向开。
2. 空手右键打开界面，输入**车站名 / 地址标签名 / 车辆标签名**，按「启程」（或回车）。
3. 空手**潜行**右键 = 清除目的地并停车。
4. 目的地在本台背后时，它会拒绝启程并在界面标 `WRONG WAY`、日志写明原因——换一台朝那个方向的控制台，
   不会倒车过去。

它和物理驾驶台的分工：驾驶台跑**时刻表**（条目、等待、连挂）；自动驾驶台只做**一段行程**——
寻路、沿进路开、扳道岔、看信号、PID 调速、到站停。两者都装在同一辆车上时不会打架：
驾驶台装了时刻表就由驾驶台当班，驾驶台空闲则由自动驾驶台当班，另一方**不下发任何指令**。

| 状态 | 含义 | 比较器输出 |
|---|---|---|
| 待命 | 没有目的地 / 未启程 | 0 |
| 规划进路中 | 等地面层给进路 | 4 |
| 自动行驶中 | 沿进路绿灯运行 | 8 |
| 减速接近 | 信号 / 弯道 / 目的地 | 11 |
| 停车等待 | 红灯、脱轨、进路失败、红石急停 | 15 |
| 已到达 | 到达目的地 | 2 |

核心做法（细节见 [`docs/AUTOPILOT.md`](docs/AUTOPILOT.md)）：

- **机械动力时刻表**：控制台左侧是时刻表槽，装入 Create 的 **Train Schedule**（潜行右键或放进槽里），
  按「启程」就按它执行：目的站、定时等待、循环都由 Create 时刻表本身定义，本模组不再维护另一份时刻。
- **站到站寻路复刻原版**（`train/CreatePathfinder`）：把 Create `Navigation.search` 的前沿队列、
  A* 启发、逐边只访问一次、信号/车站/其他列车的惩罚、`canTravelTo`/`canNavigateVia`/`canApproachFrom`
  整套搬了过来；目标为车站时走这条路，地址标签/车辆标签仍用几何寻路兜底。
- **沿进路节点跟随**（`control/RouteProgress`）：目标永远是下一个轨道节点，剩余距离按弧长累加，
  所以弯道、环线、回头线上的减速曲线仍然正确。
- **道岔**：进路授予时全扳一遍；行驶中在**接近岔路口前**按路线顺序重扳（`alignSwitchesAhead`），
  被玩家锁定的道岔拒绝驱动并记日志。
- **信号**：只沿**本台自己的行驶方向**（进路节点序列）逐边读取前方信号机；红灯按
  `brakeMargin` 的匀减速曲线停车，距离未知时直接停。已经过去的信号会被跳过。
- **单向行驶**：控制台只朝**屏幕背面**开（也就是操作员站在屏幕前看的方向）。目的地/进路起点在本台
  背后时**拒绝启程**（界面显示 `WRONG WAY`，日志说明原因），不会倒车；要双向运行就装两台，一台朝一头。
- **PID**：前馈 + 比例/积分/微分（测量微分、积分限幅、条件积分抗饱和），输出 > 0 牵引、< 0 制动。

Drive By Wire 通道（拿 `drivebywire:wire` 右键方块后滚轮切换）：

| 通道 | 用途 |
|---|---|
| `raildispatch:autopilot_forward` | 前进牵引 0..15 |
| `raildispatch:autopilot_brake` | 转向架自身制动（停稳保持）0..15 |

**没有后退通道**：控制台不提供反向推力，所以也不需要它。通道名与驾驶台**故意不同**，两个方块可同时
装在一辆车上而互不覆盖；方块被拆时两个通道会清零。

> ⚠️ **牵引必须自己接线。** 本模组不直接驱动转向架：拿 `drivebywire:wire` 把
> `autopilot_forward` 接到车上的**传动箱/驱动源**，把 `autopilot_brake` 接到转向架刹车。
> 只放方块不接线，车会刹、会转向架抱闸，但**不会走**——这是 Drive By Wire 的设计，和物理驾驶台一致。

红石输入是**紧急停车**：充能即解除自动驾驶、释放进路、抱闸；红石撤销后**不自动恢复**，需重新启程。

## 时刻表新增操作

注册在 Create 的时刻表指令扩展点上（和 Railways、铁路导航用的是同一个公开入口）：

| 指令 | 参数 | 作用 |
|---|---|---|
| `连挂车辆` | 车辆标签 | 驾驶台以该标签寻址目标车辆，接近到 `coupleRange` 内后用 Simurail 车钩连挂 |
| `按去向调车` | 地址标签 | 以该去向编码寻址股道 |

在 Create 自己的时刻表界面里编辑即可（这两个指令类型会出现在类型列表里，并自带输入框）。

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| 驾驶台一直是"空闲" | 看日志有没有 `Physics integration unavailable`；若物理桥不可用则无法认车。也可用**车辆标签**右键驾驶台显式绑定。 |
| 一直"申请进路中" | 前方区间被别的车占着，或没有可用进路。右键**调度中心**看它把进路给了谁。 |
| 红灯不停 | 检查 `stopOnDanger`；以及 `lookahead` 是否够远（信号机在 64 格外时看不见）。 |
| 道岔不动 | Create 本身没有道岔方块；装 **Create: Railways** 才会被驱动。日志里 `Track network ready, N switch driver(s)` 的 N 为 0 就说明没有可用驱动。被玩家锁定的道岔会被拒绝驱动（日志有记录）。 |
| 连挂失败 | 目标车辆或本车没有 Simurail 自动车钩；消息会显示 `no coupler available`。 |
| 车不动 | 牵引是靠给物理刚体施加**质量标定的冲量**实现的。若车体质量异常（例如 0），冲量也为 0。日志里有 `Physics bridge failed while ...` 就说明查询失败了。 |
| 静止起步方向不对 | "前进方向"在静止时由车体姿态的局部 +Z 推断（Minecraft 实体朝向约定）。若你的车体局部轴不同，起步会朝错方向；一旦动起来就会改用速度方向自我纠正。 |
| 自动驾驶台不驱动 | 也看"物理车辆"是否认出：日志里 `Autopilot console ... found no physics vehicle` 就说明它没在车上。若同车驾驶台装了时刻表，自动驾驶台会**主动让位**（这是设计）。 |
| 自动驾驶台提示 `WRONG WAY` | 目的地/进路起点在本台驱动方向的背面，或屏幕朝向装反了。转 180° 再放，或换一台朝该方向的控制台——本台**只朝屏幕背面开，不会倒车**。 |
| 自动驾驶台到站停不准 | 到达判定用 `driving.arriveRadius`（默认 5 格）。地址牌离轨道太远会进不了半径，此时会在越过 3 格内兜底停车。 |
| 转向很弱或很猛 | 转向惯量用的是标量估计（`质量 × 4.0`）。这是已知近似，见 [`docs/DESIGN.md`](docs/DESIGN.md) §9.6。 |
| 日志里有 `bogey override field was not found` | Simurail 改了那个字段名。**不影响牵引与制动**（它们走刚体），只是失去向前兼容的那条通道。 |
