# 进游戏验收清单

我（开发端）**无法启动游戏**：这台机器没有外网、没有 Gradle 依赖缓存，`runClient` 跑不起来。
所以运行时行为需要你按下面的顺序验一遍。每项都写了「预期」和「不对时看哪里」，
这样即使出问题也能快速定位到是物理层、Create 层还是我自己的逻辑。

建议开一个**超平坦创造世界**，装好 Create + Aeronautics + Simurail + Sable（+ 可选 Railways）。

---

## 0. 启动检查（最先看这个）

看 `logs/latest.log`，应该出现三行：

```
Rail Dispatch loaded: physics-vehicle automation for Create: Aeronautics
Physics bridge ready: <某个类名>
Track network ready, <N> switch driver(s) registered
```

| 现象 | 含义 |
|---|---|
| 没有第一行 | 模组没加载：检查 `mods.toml` 依赖是否满足（本模组**要求** simurail 与 sable）。 |
| 有 `Physics integration unavailable` | 物理桥装配失败，**后面 4~10 项都会不工作**。把异常栈发我。 |
| 有 `Create integration unavailable` | Create 对接失败，第 5、8、9 项会不工作。 |
| `N switch driver(s)` 的 N 是 0 | 没装 Create: Railways，或它版本不匹配 → 第 8 项的"扳道岔"不会发生（进路仍会锁闭）。 |
| 出现 `computerOverrides` 相关的 WARN | Simurail 改了那个字段名 → 牵引/制动/转向指令发不进去（第 4、5、6 项全失效）。这是最需要回报的一类问题。 |

---

## 1. 方块与物品能看到

- `/give @s raildispatch:physics_cab`（reverser / dispatch_center / address_plate / vehicle_tag / address_tag 同理）。
- **预期**：物品栏图标正常，放下去有模型、有贴图（驾驶台是深色面板带蓝色屏，换向器是橙色带箭头，地址牌是薄黄板）。
- **不对时**：如果方块**隐形但能撞到**，就是资源问题——跑 `tools\validate-resources.ps1`，它专门查这个。

---

## 2. 标签流程（不依赖物理车）

1. 铁砧上把 `vehicle_tag` 改名为 `测试车`。
2. 右键一个**没有被组装**的普通方块。
3. **预期**：提示「标签"测试车"未绑定任何车辆」（红色）。说明它确实在找车，只是没找到。
4. 直接右键空气？
5. **预期**：不改名的标签右键任意方块 → 提示「请先在铁砧上给标签改名」。

---

## 3. 驾驶台界面与装入时刻表

**先确认这一项**，因为"右键没反应"最常见的两个原因都在这里。

1. **空手右键** `physics_cab`。
2. **预期**：出现一个深色面板界面，左侧一个槽位、下面 9×3+9 的玩家背包，右侧显示
   `时刻表 --`、`状态 空闲`、`前方信号 无信号`、`速度 0.0 m/s`、`进路 free`、`bogeys: 0`。
3. 试着把**不是时刻表**的物品放进槽位。
4. **预期**：放不进去（槽位拒绝非时刻表物品）。
5. **潜行 + 右键**驾驶台（手上拿着 Create 时刻表）。
6. **预期**：提示「已装入时刻表」，界面里 `时刻表 1/N`；换成**潜行 + 空手右键**应提示「已取出时刻表」。
7. **不对时**：
   - 空手右键毫无反应 → 大概率是模组没加载（见第 0 项）或客户端界面注册失败（日志里搜 `raildispatch`）。
   - 手持时刻表**不潜行**右键 → 打开的是 **Create 自己的**时刻表编辑界面，这是正常的，不是 bug（见上面第 2 步的说明）。
   - 界面打开后立刻自己关掉 → 客户端找不到方块实体，请回报。

---

## 4. 认车 + 牵引/制动（需要物理车）

1. 用 Aeronautics 的方式组装一辆有 **Simurail 物理转向架**的车，把驾驶台装在车上一起组装。
2. 右键驾驶台。
3. **预期**：`bogeys:` 后面出现非 0 的数字（说明找到了物理车与它的转向架）。
4. **不对时**：
   - `bogeys: 0` 且 `状态 空闲` → 物理桥没认出车。试试用**车辆标签右键驾驶台**显式绑定（第 2 项的改名标签）。
   - 仍然 0 → 把日志里 `Physics bridge` 那行的类名和是否有 WARN 发我。

---

## 5. 信号机前停车（核心行为）

这是最能说明"看懂信号"的一项。

1. 在车前**轨道上**放一个 Create 信号机，设成红灯（或者干脆用一列占据区间的车让它变红）。
2. 给驾驶台一张有目的地的时刻表，让它跑起来。
3. **预期**：
   - 界面 `前方信号` 变 `红灯停车`；
   - `状态` 依次经过 `运行中 → 接近 → 信号机前停车`；
   - 车**在信号机前停住**，不会冲过；
   - 比较器输出到 15。
4. 把信号机放行（绿灯）。
5. **预期**：`状态` 回到 `运行中`，车继续走。
6. **不对时**：
   - `前方信号` 一直 `无信号` → `lookahead`（默认 64 格）内没找到信号机，或者 Create 层没接上（看第 0 项）。
   - 有红灯但不停 → 检查配置 `stopOnDanger`；以及 `brakeMargin` 是否被设成负值之类。

**注意**：物理车的"速度"来自 Sable 的刚体，若你的车还没被物理引擎接管（没组装），它不会动，这是正常的。

---

## 6. 换向器

1. 把 `reverser` 装在物理转向架旁边（8 格内）一起组装。
2. 用红石给它 8 格信号。
3. **预期**：右键显示 `转向 +0.00`；比较器输出约 8；界面/聊天里显示驱动到的转向架数量非 0。
4. 给 15 → 转向应接近 `+1.00`；给 1 → 接近 `-1.00`；给 0 → 转向回到 0 且标记为无效（放开）。
5. 把方块放成倒向（或用 `inverted` 属性）→ 15 应给出 `-1.00`。
6. **不对时**：如果"驱动到的转向架数量"是 0，说明它没找到同车的转向架（第 4 项的先决条件）。如果数字对但车不转，见第 0 项的 `computerOverrides` WARN。

---

## 7. 驾驶台优先于换向器

1. 让驾驶台接管这辆车（第 4 项成功）。
2. 给换向器红石信号。
3. **预期**：换向器**不再**驱动转向架（避免两个控制器抢同一个转向架），驾驶台的转向指令生效。
4. 让驾驶台空闲（取走时刻表）。
5. **预期**：换向器重新开始按红石工作。

---

## 8. 调度中心与进路

**先测放置方式**（它和信号机一样是两步的）：

1. 手持 `dispatch_center`，**不选轨道**直接右键一个地面方块。
2. **预期**：拒绝放置，并提示类似"未选择轨道"（`track_target.missing`）。这是 Create 的行为。
3. 手持它 **右键铁轨**。
4. **预期**：出现选中反馈（Create 的音效/描边），物品上记录了这条轨道。
5. 再 **右键铁轨旁的地面**放下。
6. **预期**：方块落下；右键它应显示「调度中心：持有 0 条进路，作用范围 256 格」**以及「已锁定轨道 X」**。
7. 潜行 + 右键铁轨。
8. **预期**：清除已选轨道。
9. 拆掉调度中心，再右键轨道图相关处。
10. **预期**：不留幽灵点位（`IBE.onRemove` 会把它从轨道图上摘掉）。

**再测仲裁：**

11. 让**两辆车**同时申请会经过同一个岔路口的进路。
12. **预期**：第二条被拒绝，右键调度中心能看到它把进路给了谁；被拒的车界面里 `进路` 不是 locked。
13. 让第一辆车走掉/停住不动超过 `routeTimeoutTicks`（默认 600 tick = 30 秒）。
14. **预期**：进路被自动释放（防幽灵锁闭），第二辆车随后能拿到。
15. 装了 Create: Railways 时，进路上的道岔应被扳到对应支线；日志里 `switch driver(s)` ≥ 1。

---

## 9. 时刻表新指令

1. 拿一张 Create 时刻表，打开它的编辑界面。
2. **预期**：指令类型列表里能看到 **`连挂车辆`** 和 **`按去向调车`**，选中后有输入框可以填标签名。
3. 填一个已绑定的车辆标签，保存。
4. **预期**：驾驶台读到它，`状态` 进入 `连挂中`，并朝目标车开过去。

---

## 10. 连挂

1. 两辆车**都装 Simurail 自动车钩**。
2. 给主动车一张"连挂车辆 → 目标车标签"的时刻表。
3. **预期**：主动车接近到 `coupleRange`（默认 8 格）内 → 车钩互设 partner → 两车形成一个物理整体（Sable 约束生效，能一起被推动）。
4. **不对时**：
   - 提示 `no coupler available` → 有一侧没有车钩。
   - 提示车钩类型不兼容 → Simurail 的 `CouplerType.canConnectTo` 判定不能连，换个车钩类型。

---

## 11. 驼峰场去向识别

1. 在两条股道上各放一块 `address_plate`。
2. 铁砧改名两块 `address_tag`：`1道`、`2道`。
3. 用 `1道` 右键第一条股道的地址牌；用 `2道` 右键第二条。
4. 用 `2道` 右键某辆车（表示这车要去 2 道）。
5. **预期**：右键地址牌提示「去向编码：1道 / 2道」；比较器给有编码的地址牌输出 15。
6. 给驾驶台一张"按去向调车 → 2道"的时刻表。
7. **预期**：驾驶台寻址到**第二条**股道（而不是第一条），并朝它开。

---

## 12. 自动驾驶台 `autopilot_console`

**先确认界面能打开并留住**（这一项最容易因为坐标空间问题失败）。

1. 把 `raildispatch:autopilot_console` 放在车上，随结构组装。
2. 空手右键。
3. **预期**：深色面板，一个输入框、三个按钮（启程 / 停车 / 清除），下方是状态、速度/目标、
   信号、进路、牵引/制动。
4. **不对时**：界面一闪就关 → 菜单的 `stillValid` 或客户端找不到方块实体，回报日志。

**再测一段直线**：

5. 输入一个已知车站名，按「启程」。
6. **预期**：
   - 提示「自动驾驶已启程：<名字>」；
   - 状态 `规划进路中 → 自动行驶中`；
   - 进路显示 `locked, <N> blocks, <i>/<n>`；
   - 车开动，速度/目标随剩余距离下降。
7. 日志里应有 `Autopilot console ... route to '<名字>' GRANTED`。

**信号**：

8. 在车前放一个红灯。
9. **预期**：状态 `减速接近 → 停车等待`，车在信号机前停住；比较器输出 15。
10. 放行 → 状态回到 `自动行驶中`。

**机械动力时刻表**：

10f. 用 Create 的 Train Schedule 编辑两条目的站（可带 Timed Wait 条件），潜行右键装进控制台
     左侧的槽（或直接放进槽里）。按「启程」：应执行第一条，而不是目的地输入框。
10g. 到站后若有 Timed Wait，状态应为 `Holding`，等待结束后自动 `advance` 到下一条。
10h. 打开 Create 时刻表的 cyclic：最后一条后应回到第一条；关闭后应显示 `schedule complete`。
10i. 把时刻表取出（空手潜行右键）：应立即停止执行，表物品停在当前 `savedProgress`。
10j. 没有装表时，「启程」仍按目的地输入框跑单次；装了表后目的地输入框不参与。

**原版寻路（站到站）**：

10c. 让目的地是一个**车站**，日志里应出现 `Native path search: station '<名字>', ...`。
10d. 与一列 Create 原版火车跑同一条站到站线路对比：经过的岔路口/支线应当一致（原版会因红灯、
     占用区间、别的列车而绕行，复刻版也应当绕同一侧）。
10e. 若日志只有 `planRoute: ...` 而没有 `Native path search`，说明落到了几何兜底：
     检查目的地是否解析成车站（地址牌/车辆标签本来就走兜底），以及车站是否在车辆同一张轨道图上。

**道岔 / 弯道上的信号（本次修复的重点）**：

10b. 在一个道岔的**两条支线各放一盏信号机**（一条红、一条绿），让自动驾驶台的进路走其中一条。
11b. **预期**：界面上的 `前方信号` 是**本进路那条支线**的信号，不是隔壁支线的；红灯会停，绿灯通过。
12b. 把进路改成弯道（或用一段曲线轨道），在弯道后放红灯。
13b. **预期**：仍然能读到该红灯并停车，而不是显示 `无信号`。
14b. **不对时**：记录当时的进路、两条支线的信号颜色、界面显示，以及日志里 `signal` 相关行。

**道岔**：

11. 进路经过一个 Railways 道岔。
12. **预期**：授予时道岔已扳向路线支线；接近时若手动扳回，约 1~5 秒内会被重新扳回。
13. **不对时**：日志 `Switch at ... is locked` → 玩家锁定了道岔（设计如此）；
    没有 Railways → 道岔不会动（进路仍会锁闭）。

**Drive By Wire（单向）**：

14. 拿 `drivebywire:wire` 右键自动驾驶台，滚轮切换通道。
15. **预期**：只出现两个通道 `raildispatch:autopilot_forward` 和 `raildispatch:autopilot_brake`，
    **没有** `_backward`。
16. 把 forward 接到传动箱，启程后通道值随 `牵引` 百分比变化；停稳后 brake 为 15、forward 为 0。
17. 拆掉方块。
18. **预期**：两个通道归零（不留幽灵油门）。

**单向 / WRONG WAY**：

19. 让**屏幕朝向目的地**（这样驱动方向正对目的地背面，或让目的地在车尾），按启程。
20. **预期**：
    - 界面出现 `WRONG WAY`，状态回到待命；
    - 日志 `destination '...' resolves behind this console ... refusing to reverse`；
    - 车**不动**、不倒退；进路已释放。
21. 转 180° 放好方块（或换车头那台控制台）再启程。
22. **预期**：正常行驶；**全程没有后退通道/倒车**。
23. **不对时**：若车仍然倒着走，说明前进通道接到了反向传动箱——这是接线问题（本台不提供后退通道）。

**红石 / 互斥**：

22. 给自动驾驶台一个红石信号。
23. **预期**：立即停车、状态 `停车等待`、比较器 15；撤销红石后**不会**自动恢复，必须重新启程。
24. 同车再放一台物理驾驶台并装入时刻表，然后启程自动驾驶台。
25. **预期**：自动驾驶台让位（`detail = schedule cab in charge`），不再驱动；取走时刻表后重新启程可接管。

**到达**：

26. 让车开到目的地。
27. **预期**：状态 `已到达`，车停稳，进路释放（右键调度中心/别的车可申请同一段），比较器 2。

## 回报问题时请附上

1. `logs/latest.log` 里所有含 `Rail Dispatch`、`Physics bridge`、`Track network`、`raildispatch` 的行；
2. 出问题那一项的**编号**；
3. 驾驶台界面截图（界面上的状态/信号/进路文字是最直接的线索）；
4. 如果某项在某个第三方 mod 上炸了，附完整异常栈。

有了这些我可以直接定位到是 `physics/`、`train/` 还是业务层的问题。
